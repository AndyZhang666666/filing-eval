## 为什么不用 RAGAS / DeepEval 这类现成的忠实度评测

它们给一个 faithfulness 分数。这个项目要的是**定位到字**的错误清单 —— 审核员看的不是 0.83，是"第二句的 12 亿错了"。分数是副产品，断言列表才是产品。

另一个原因：现成框架的 prompt 是黑盒。这个项目的核心交付物就是 prompt 的迭代过程（v1 → v1.1 → v1.2 各自解决了什么），黑盒框架把这条线抹掉了。

## 为什么是两个范式而不是一个

creative-eval 做主观打分（1–5 分 rubric），这个项目做客观核验（断言分类）。主观分天生有方差，事实判定近乎二元；混在一套指标里，事实判定的可靠性会被主观分的方差稀释。两个项目刻意用不同范式，是为了让面试官看到：**知道什么问题该用什么评法**。

## 为什么覆盖率只算 high

见 README。补一句：这个决定的代价是 `importance` 口径变成了裁判的另一个自由裁量点。v1.2 用明确定义把它钉住，但钉得住多少，要靠跨模型测试验证。

## 为什么 temperature 0

回归测试要可复现。σ = 0 是可复现的证据，不是正确的证据 —— 这两件事 README 里分开写了。

## 为什么困难集不并入主集

主集是回归基线，数字应该稳定；困难集是探上限，数字应该波动。混在一起，上限的波动会污染基线的稳定。两个 latest 文件（`latest.json` / `latest-hard.json`）就是这个原因。

## 为什么争议样本从分母剔除而不是改标注

h05 的两种读法都站得住。改标注迁就裁判，等于把测试集调成永远通过；保留在分母里当"漏报"，等于惩罚裁判做了一个合理判断。剔除 + 显式列出，是唯一诚实的做法。

## 为什么打分逻辑要和采样逻辑分开

`lib/score.js` + `scripts/rescore.mjs`。改判据不重跑模型，历史结果可以重新解读。代价是：重算出来的数字必须标明是哪版判据 —— 否则不同判据的数字混在一张表里，会得出"模型变好了"的错误结论，其实只是及格线动了。

## 什么时候会推翻上面的决定

- 如果跨模型测试显示 `importance` 口径在不同模型上漂移超过 0.2，覆盖率的分母定义要重想
- 如果 Andy 复核后认为「编造归因」比「数字写错」后果更重，权重排序要反过来
- 如果困难集扩到 30 条以上还是全对，说明我构造困难样本的能力到头了，需要换人出题
