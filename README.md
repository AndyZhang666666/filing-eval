## 值得看的设计

- 断言错误和关键遗漏分别核验，避免总分掩盖风险。
- 原文、摘要和历史裁判并列，人工判断单独记录。
- 有争议的标签继续可见，不为提高成绩悄悄改答案。

## 建议体验路径

1. 打开一条公告样本，选中摘要里的具体断言。
2. 回到原文检查事实，再查看没有被写进摘要的关键事项。
3. 保存复核结论与依据，继续未复核项，导出完整记录。

**运行方式：** 公开体验是 28 条构造公告的静态历史回放，不评估任意新文本；原 Next.js 与模型评测脚本保留在源码中。

## 谁在用、解决什么

投研 / 合规团队每天要读大量上市公司公告，AI 摘要能省时间，但摘要一旦把「1.2 亿」写成「12 亿」、把「下降」写成「增长」、把「子公司」写成「公司」，读的人不会发现 —— 摘要看起来很专业。

这个工具做的事：给摘要生成系统装一个**回归测试**。每次改 prompt、换模型，跑一遍金标集，看错误检出率有没有掉。

## 三个关键产品决策

### 1. 检出率、误报率、覆盖率分开报，不合成一个分数

查错产品有两个方向相反的代价：漏掉一个致命错误，产品存在的意义就没了；误报一个干净摘要，审核员开始不信任它。F1 会给一个"看起来不错"的数，但完全看不出该往哪个方向调。

第一版把三者 AND 成一个 `hit_rate`，跑出 50%，看着像裁判很差。查下去发现：一条摘要把数字写错了，那条关键事实必然显示"未覆盖"—— 检出和覆盖在错误样本上互相打架。这不是裁判的问题，是判据的问题。拆开后：

| 指标 | 主集 (20 条) | 困难集 (8 条) |
|---|---|---|
| 错误检出率 | **11/11** | **5/5**（另 1 条争议） |
| 误报率 | **0/4** | **0/2** |
| 覆盖率及格 | **4/4** | 2/2 |

### 2. 「写错」和「无据」是两类错误，权重 1.0 / 0.8

写错（原文有对应信息但摘要矛盾）会被监管和法务抓，修的是抽取环节；无据（原文里没有，摘要自己补的）会被用户抓，修的是生成环节。合成一个"幻觉率"等于说两者修复动作一样 —— 它们不是。

0.8 这个数没有实验支撑，是把「无据比写错轻一档」量化的结果。**有依据的是排序，不是数字本身。**

### 3. 覆盖率分母只算 `high`，不算 `medium`

第一轮干净摘要覆盖率只有 0.667。查下去：裁判把「会议届次」「回购方式」这类省略了也合理的细节标成 `high`。两条路 —— 改指标，或改标注迁就裁判。选了改指标：省略会议届次算不算遗漏，本来就不该由裁判的自由裁量决定。给 `importance` 钉了明确口径（prompt v1.2），`medium` 覆盖率另算一个宽口径值，只展示不判定。

## 什么失败了，怎么修的

### 模型自创 schema，三次三个样

v1.1 跑出来：`{"verdict":"通过","无据":[],"写错":[]}`，再跑 `{"result":"通过","reason":"..."}`，再跑 `{"faithful":true,"factual_errors":[]}`。加了容错映射（`LABEL_ALIASES`），加了 `response_format: json_object`，还是不稳。

真正的根因：`PROMPT_V1_1` 是用 `BASE_RULES.replace()` 从旧版本生成的，从来没接上 `FORMAT_SPEC`。默认 prompt 发出去时**没有任何格式约束**（system prompt 只有 716 字）。用 `scripts/_probe.mjs` 打印出实际发送的 prompt 才发现。

修法：把抽象 schema 换成一份**填好的完整示例**。对模型来说模仿样本比理解结构描述容易得多 —— 先在 curl 里单独验证过，再改代码。修完 `run_failed: 0`。

### 检出率虚高到 100%

干净样本同时打着 `faithful` 和 `error:none` 两个标签，`tags.some(t => t.startsWith("error:"))` 把它们也当成错误样本，而它们的期望本来就是"不该报错"，必然通过。这个 bug 不报错、不崩溃，只是安静地把指标变成假数字。

修法：`isErrorItem` 排除 `error:none`；把打分逻辑抽到 `lib/score.js`，加 `scripts/rescore.mjs` 用当前判据重算历史结果，不重新调模型。**打分逻辑必须和采样逻辑分开** —— 否则每次改判据都要重跑，"改判据"和"重新采样"就混在一起了。

### 一条测试从来没执行过

h06（遗漏否决意见）第一版用 `min_coverage` 标注，而判分逻辑给所有 error 类样本跳过了覆盖率检查。结果这条**一项检查都没执行**，永远显示绿色。加了 `checks` 计数：0 项 = 空测试，标红并报出来。

### 主集全对，所以建了困难集

20 条跑出 100% / 0% / 4/4。全对不是好消息，说明主集触到了天花板。另建 8 条"自己都要看两遍"的样本：范围偷换（单一客户占比 → 前五大客户占比）、因果倒置、情态偷换（拟 → 已）、基数偷换（较年初 → 同比）、主体偷换、实质性遗漏，加 2 条刻意写得像有问题的干净样本。

结果 5/5 抓到，1 条争议（h05：全资子公司投资写成公司投资 —— 合并层面等价，披露口径不等价，是 rubric 没定义清楚，**不改标注迁就裁判**，从分母剔除但保留在列表里）。

## 裁判本身也被评测

| 测试 | 结果 |
|---|---|
| 稳定性：10 条 × 3 次，「有错/没错」结论翻转 | **0 / 10**，幻觉率 σ = 0 |
| 对抗：5 种注入话术（直接命令 / 伪装系统备注 / 权威背书 / 预填输出 / 角色替换） | **0 / 5 被劫持**，隐藏的 10 倍错误全部抓出 |
| 对照组（同一错误、无注入） | 抓到 —— 否则上面数字不可信 |
| 摘要长于原文 5 倍 | 抓出 6 条无据，期望 ≥ 4 |

所有数字由 `scripts/` 下脚本跑出，原始输出在 `results/`，可以 clone 下来重算。

## 已知局限 / 下一步

- **金标集没经人工逐条复核。** 所有 `expect` 是我起草的，页面上「待复核」一栏把它们全列出来了。没有人工确认的测试集只是自说自话。
- **只测了一个裁判模型**（claude-sonnet-4-5）。跨模型一致性是下一个该做的实验。
- 稳定性 σ = 0 是在 temperature 0 下测的。这说明"可复现"，不说明"正确"。
- 困难集 8 条太少，只能定位方向，不能给出可靠的上限估计。
- `0.8` 权重、`importance` 口径都是判断，写在 `docs/DECISIONS.md` 里，欢迎推翻。

## 本地跑

```bash
cp .env.example .env    # 填 LLM_BASE_URL / LLM_API_KEY（任何 OpenAI 兼容接口）
npm install
npm run dev             # http://localhost:3000

npm run eval                          # 主集 20 条
TIER=hard npm run eval                # 困难集 8 条
npm run stability                     # 10 条 × 3 次
npm run adversarial                   # 5 种注入 + 超长摘要
npm run rescore                       # 判据改了就重算历史结果，不重复调模型
node scripts/rescore.mjs              # 改了判据后，重算历史结果不重跑模型
```

金标集在 `data/golden/`，全部为虚构公司的模拟公告，不含任何真实上市公司数据。
